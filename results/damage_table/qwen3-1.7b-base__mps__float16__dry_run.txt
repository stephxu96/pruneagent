How rounds work. Each round, propose 1–3 candidates. Each candidate is a list
of (layer, method) choices, applied together to the current model, one
fixed-size step per choice. Code measures each candidate's real perplexity. A
candidate is rejected if its perplexity is more than 15% above the current
model's (above 11.50 this round). Of the rest, code keeps the one with the
smallest perplexity increase per MB freed; if two are exactly tied, the one

used. You have 40 rounds left. The run ends as soon as a kept step brings the
model within the memory limit. It also ends after 5 rounds in a row without a
kept step (0 so far), after 40 rounds or 60 replies in all, or after 3
unusable replies in a row.

Candidates are your experiments: make them test different ideas, not small
variations of one idea. Small steps let you re-measure before committing
further. You can return to an earlier kept plan, but a later step cannot undo
the damage of an earlier one.

Steps free different amounts of memory. Judge a step by perplexity increase
per MB freed, not by perplexity increase alone.
